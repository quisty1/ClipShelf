# Проверки ClipShelf 1.0.0

Дата: 19 октября 2026 года. Окружение: macOS 27.0.1, Apple Silicon, Swift 6.2.4 Command Line Tools.

## Выполнено

- Полный набор `swift run ClipShelfChecks`: **18 проверок, 0 ошибок**.
- Поиск по 1000 записям: около **0,01 секунды** на этом Mac. Это замер двух поисковых запросов, а не времени запуска всего приложения.
- Release-сборка arm64 без сторонних зависимостей.
- Локальная подпись `.app`: `codesign --verify --strict` — успешно; Info.plist — корректен.
- Готовая `.app` из outputs запущена через Launch Services, отдельно от SwiftPM.
- В нативном окне проверены тёмная и светлая темы, поиск, смена выбора стрелками, создание коллекции, настройки, длинный текст, фильтр изображений и предпросмотр.
- При запуске без тестового режима проверено приветственное окно с пустой библиотекой.
- Независимая проверка кода: выявлены и исправлены три существенных случая. Для каждого добавлена проверка, воспроизводившая проблему до исправления: смена источника между копированием и опросом, ошибка первого сохранения с изображением, HTML без plain text.

## Что покрывает автоматика

Поиск и дедупликация; различение форматов; ссылки; преобразования текста; пауза, исключения и метки конфиденциальности на уровне политики; курсор поколений буфера и смена источника; защищённые записи при очистке; удаление коллекции без потери записей; независимость шаблонов; полная очистка; ограничение истории до 1000 записей; перезапуск базы; файлы изображений; восстановление после первой ошибки записи; чтение и запись RTF/HTML, HTML-only, изображений, пропуск файлов и собственных записей.

Тесты используют временные каталоги и отдельные NSPasteboard. Общий буфер пользователя тестовым модулем не читается и не меняется. Ошибка хранилища воспроизводится через внедряемый интерфейс сохранения; успешное сохранение и восстановление отдельно проверяются на настоящем Core Data / SQLite.

## Требует ручной приёмки после выдачи разрешений

Не проверены сквозным сценарием:

- Фоновое чтение общего буфера из Safari и TextEdit после выбора «Всегда разрешать».
- Отказ и отзыв разрешения на чтение в системных настройках.
- Отправка ⌘V в другое приложение после выдачи «Универсального доступа», включая отзыв доступа и смену фокуса во время ожидания.
- Изменение глобальной горячей клавиши и конфликт с другой программой.
- Запуск при входе после перезагрузки.

Политики и проверки фокуса реализованы, но эти системные сценарии нельзя считать подтверждёнными только по тестам отдельных функций. Разрешения macOS не были выданы автоматически. Для приёмки используйте новый несекретный текст и тестовый документ; порядок выдачи разрешений указан в инструкции.

## Отличия от первоначальной технической схемы

- Core Data / SQLite вместо SwiftData: в установленном CLT нет SwiftDataMacros; полный Xcode для сборки не требуется.
- Исполняемый модуль ClipShelfChecks вместо Swift Testing: установленный фреймворк не содержит требуемого модуля _Testing_Foundation. Проверки по-прежнему автоматические и возвращают ненулевой код при ошибке.
- Сборка локально подписана ad hoc, без Developer ID / нотарификации, для использования на данном Mac.
- Неоднозначные копирования при смене приложений пропускаются ради соблюдения исключений.
